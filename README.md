# RAG App

A fully local Retrieval-Augmented Generation app. Upload PDF/TXT documents, then
chat with them. Everything runs on your machine — no cloud APIs.

- **Embedding**: `nomic-embed-text` (Ollama)
- **Generation**: `gemma3:4b` (Ollama)
- **Vector DB**: Qdrant (local, Docker) — chunk embeddings
- **Database**: Postgres (local, Docker) — chat history, document metadata, raw files, tags
- **Backend**: FastAPI
- **Frontend**: React + TypeScript (Vite) + Tailwind

## Prerequisites

- [Ollama](https://ollama.com) installed and running
- [Docker](https://docs.docker.com/get-docker/) (for Qdrant)
- Python 3.10+
- Node 18+ and `pnpm` (`npm i -g pnpm`)

## Pull the models

```bash
ollama pull nomic-embed-text
ollama pull gemma3:4b
```

Make sure Ollama is serving at `http://localhost:11434` (it does by default).

## Start everything

**1. Qdrant + Postgres**

```bash
docker compose up -d
```

This starts Qdrant (`localhost:6333`) and Postgres (`localhost:5432`, db/user/pass all `rag`).
The schema in `backend/schema.sql` is applied automatically on first boot and re-checked
(idempotently) on every backend startup.

**2. Backend** (from `backend/`)

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload          # http://localhost:8000
```

**3. Frontend** (from `frontend/`)

```bash
cd frontend
pnpm install
pnpm dev                            # http://localhost:5173
```

Open http://localhost:5173, upload a document, and start asking questions.

## API

| Method | Path                     | Description                                                            |
| ------ | ------------------------ | ---------------------------------------------------------------------- |
| POST   | `/upload`                | Upload a PDF/TXT (+ optional `tags`); chunks, embeds, indexes, stores. |
| POST   | `/chat`                  | `{ "question", "chat_id"? }` → streamed answer; persists the turn.     |
| GET    | `/chats`                 | List chat threads (newest first).                                      |
| GET    | `/chats/{id}/messages`   | Messages in a thread.                                                  |
| GET    | `/documents`             | List indexed documents with tags + chunk counts.                      |
| GET    | `/health`                | `{ "status": "ok" }`                                                   |

`/chat` returns the thread id in the `X-Chat-Id` response header so the client can keep
appending to the same conversation.

## Notes

- Qdrant collection `documents` is auto-created on backend startup (768-dim, cosine).
- Postgres tables (`documents`, `chats`, `messages`) are created from `backend/schema.sql`.
- Chunking: 500 chars with 50-char overlap.
- `qdrant_storage/` and `pg_data/` are generated by Docker — don't edit them.
- Override the DB connection with `DATABASE_URL` (defaults to `postgresql://rag:rag@localhost:5432/rag`).
